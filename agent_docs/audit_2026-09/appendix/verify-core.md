## Missed by the reports (with evidence)

1. **The bridge is the semver oracle and none of the reports used it that way.** `whatsapp-rust-bridge/Cargo.toml:145` tracks `branch = "main"`. It reads 22 `MemoryReport` fields by name (`wasm_client/connection.rs:550-580`), matches 55 feature-error variants (`errors.rs`), and implements `SignalStore`/`AppSyncStore`/`ProtocolStore`/`MsgSecretStore`/`DeviceStore` (`js_backend.rs:630-1573`). Report 1 #4, #8 and Report 2 #3, #11 are all bridge-breaking while labelled low/medium risk.
2. **Four source-scanning guard tests constrain most proposed moves and no report lists them as the first thing to update:** `tests/report_coverage.rs` (syn-parses `struct Client`, one-level `growable_path`, brace-matches `memory_report()`), `tests/subsystem_boundary.rs` (counts `feature = "..."` terms per file, budget 9, owned-file list), `tests/ab_prop_watch_coverage.rs` (textual scan of `src/` accessor args against `abprops::ALL`), `storages/sqlite-storage/src/sqlite_store.rs:6903` (self-`include_str!` scan).
3. **`wacore::types::call::MediaOffer` embeds `voip::relay_parse::RelayData` behind `#[cfg(feature = "voip")]`** — this is the cycle hazard for any `wacore-voip` crate and also the one place a public `Event` payload type changes shape with a feature; Report 3 reads it as proof the split is easy.
4. **`EventKind::RetiredPushNameUpdate`** (`events.rs:246-248`) has no `Event` counterpart; any generated 1:1 list needs an explicit "retired slot" arm.
